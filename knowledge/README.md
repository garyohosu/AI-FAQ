# knowledge/ ディレクトリ

社内IT管理部門が保有する知識資料を置く場所です。`aifaq knowledge import` が
このディレクトリ以下を走査し、対応形式のファイルを差分取り込みします。

## 対応ファイル形式

- `.xlsx` / `.xlsm` (`openpyxl` で `read_only=True`, `data_only=True` で読む。
  マクロ・外部リンク・数式は実行せず、保存済みのセル値のみを取り込む。
  非表示シートは既定で取り込まない)
- `.csv` / `.tsv` (UTF-8優先、失敗時のみCP932へフォールバック)
- `.md` (`#`/`##`/`###` 見出し単位でチャンク化)
- `.txt` (サイズ上限ごとにブロック分割)

`.xls`、PDF、Word、PowerPointはMVP対象外です。`.xlsx`または`.csv`への変換を
お願いします。

## サブフォルダとGit管理方針

| フォルダ | 用途 | Git管理 |
|---|---|---|
| `public/` | 外部に出しても問題ない一般公開情報のサンプル | **される** (実データを置いてよい唯一のフォルダ) |
| `internal/` | 社内固有の内部資料 | されない (README以外) |
| `policies/` | 社内規程・ポリシー | されない (README以外) |
| `procedures/` | 手続き・申請フロー | されない (README以外) |
| `troubleshooting/` | 障害対応手順 | されない (README以外) |
| `inventory/` | 資産・設備台帳 | されない (README以外) |
| `inbox/` | 未整理の取り込み待ちファイルの一時置き場 | されない (README以外) |

`public/` 以外に実データを置いても、`.gitignore` によりコミット対象から
除外されます。実ファイルをGit管理したい場合は、管理者が明示的に
`.gitignore` を変更してください(既定では推奨しません)。

`aifaq doctor` は、`internal/` や `inbox/` の実ファイルが誤ってGit追跡
対象になっていないかを警告します。

## Excelの推奨列構成

1行目をヘッダー行として扱います。各行は「ヘッダー: 値」の形でチャンク化
されるため、列見出しは意味の分かる名前にしてください(例: `項目`, `内容`,
`申請先`, `備考`)。

## MEMORY.md との関係

各資料は `MEMORY.md` の `## Source Map` に1エントリとして登録することを
推奨します。スコープ・優先度・状態(`active`/`stale`/`retired`/`forbidden`)
を明記すると、検索時の優先順位判定や `forbidden` 資料の除外に使われます。
