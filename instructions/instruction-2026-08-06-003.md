# instruction-2026-08-06-003

## 位置付け

この指示書は `instruction-2026-08-06-001.md` と `instruction-2026-08-06-002.md` の追加要件である。

実装時は001、002、003を合わせて読み、矛盾する場合は番号の大きい指示書を優先する。まだ実装を開始していない場合は、最初から本要件を組み込むこと。

## 追加目的

社内IT管理部門が保有するExcel、CSV、Markdown、テキスト形式の知識資料を所定のフォルダへ置き、AI FAQが安全に取り込んで検索できるようにする。

また、次のような「知識の所在と運用上の記憶」をMarkdownで残せるメモリー機能を追加する。

- どの種類の知識が、どのファイル・シートにあるか
- どの資料を優先して参照すべきか
- 社内独自用語の意味
- 古い資料、重複資料、参照禁止資料
- 未解決の知識不足
- IT管理者が決めた運用上の判断

ここでいうメモリーは、LLMの学習やモデル再訓練ではない。人間が管理するMarkdownとSQLiteへ保存した構造化メタデータを、検索・分類・ルーティングに再利用する仕組みとする。

### Git管理方針

社内資料が誤って公開リポジトリへpushされないようにする。

- `knowledge/public/` のサンプルだけGit管理を許可する
- `knowledge/internal/` 以下の実データは既定で `.gitignore` 対象とする
- `knowledge/inbox/`、`data/`、取り込みキャッシュ、抽出テキスト、ログはGit管理しない
- 各フォルダには、用途だけを説明する安全な `.gitkeep` またはREADMEを置いてよい
- 実ファイルをGit管理する場合は、管理者が明示的に設定を変更した場合に限る

## 対応ファイル形式

MVPで次の形式をサポートする。

- `.xlsx`
- `.xlsm`（セル値だけを読み、マクロを実行しない）
- `.csv`
- `.tsv`
- `.md`
- `.txt`

`.xls` はMVPでは直接サポートせず、`.xlsx` または `.csv` への変換を案内する。PDF、Word、PowerPointは今回の必須範囲外とし、後からプロバイダー方式で追加できる構造にする。

Excel読込には `openpyxl` を使用し、`read_only=True` と `data_only=True` を基本とする。

- VBAやマクロを実行しない
- 外部リンクを開かない
- 数式そのものを実行しない
- `data_only=True` で保存済みの計算結果だけを利用する
- 非表示シートは既定で取り込まない
- 取り込むシートを設定で限定できるようにする
- 行数、列数、ファイルサイズ、セル文字数に上限を設ける
- 空行や重複行を無制限に取り込まない

CSV・TSV・テキストはUTF-8を優先し、日本語Windows由来の資料に備えてCP932を安全にフォールバック候補とする。文字コードを推測した場合は取り込み履歴へ記録する。

## MEMORY.mdの役割

リポジトリ直下の `MEMORY.md` を、知識所在の最上位インデックスとする。

これは自由形式の日記にせず、一定の書式を持つ人間可読・機械可読の索引にする。

最低限、次の章を持たせる。

```markdown
# AI-FAQ Memory Index

## Source Map
## Terminology
## Routing Rules
## Important Decisions
## Known Gaps
## Retired or Forbidden Sources
```

### Source Mapのエントリ形式

各資料には一意なIDを付け、最低限次を記録する。

```markdown
### SRC-001
- path: knowledge/procedures/account-request.xlsx
- contains: アカウント申請、権限変更、退職者処理の手順
- sheets: 申請先, 権限一覧
- scope: INTERNAL
- category: account
- owner: IT管理部
- priority: high
- status: active
- last_reviewed: 2026-08-01
- valid_until:
- notes: 申請先は「申請先」シートを正とする
```

必須フィールド候補:

- `path`
- `contains`
- `scope`: `PUBLIC | INTERNAL | CONFIDENTIAL | RESTRICTED`
- `category`
- `owner`
- `priority`: `low | normal | high | authoritative`
- `status`: `active | draft | stale | retired | forbidden`
- `last_reviewed`
- `valid_until`
- `notes`

Excelの場合は任意で `sheets`、CSV・テキストの場合は任意で行範囲や見出しを記録できるようにする。

### メモリーの分割

`MEMORY.md` は全体索引と重要ルールに限定し、詳細は `memory/` 以下へ分割する。

- `memory/terminology.md`: 社内用語、略語、製品名、部門名の説明
- `memory/source-notes.md`: 資料ごとの注意、優先順位、重複関係
- `memory/decisions.md`: 管理者が決定した運用方針と理由
- `memory/gaps.md`: 未回答、資料不足、要更新事項

`MEMORY.md` から各ファイルへリンクし、孤立したメモを作らない。

## メモリーの安全規則

- パスワード、秘密鍵、APIトークン、認証コードを記録しない
- 個人情報そのものをメモリーへ保存しない
- 内部IP、ホスト名、設備資産番号などは必要性を確認し、保存する場合も外部AIへ送信しない
- AIがメモリーを書き換える場合は必ず提案状態にし、人間の承認後に確定する
- AI調査結果を自動的に `MEMORY.md` や承認済み知識へ追加しない
- 削除ではなく、原則として `retired` または `forbidden` と理由を残す
- Git管理対象のMarkdownには、公開して問題のない情報だけを書く

## 知識取り込み処理

### 基本フロー

```text
knowledge/を走査
  ↓
MEMORY.mdのSource Mapと照合
  ↓
ファイル種別・サイズ・機密区分を検査
  ↓
内容を安全に抽出
  ↓
行・見出し・シート単位でチャンク化
  ↓
Pydanticで検証
  ↓
SQLiteへ保存
  ↓
FTS5インデックス更新
  ↓
取り込み結果と警告を記録
```

### 増分取り込み

毎回全ファイルを再処理しない。

- 相対パス
- ファイルサイズ
- 更新日時
- SHA-256
- インポートバージョン

を保存し、内容が変わったファイルだけ再取り込みする。

削除・移動された資料は即時に完全削除せず、DB上では `MISSING` または `RETIRED` として追跡できるようにする。

### 出典情報

取り込んだ知識には、可能な範囲で次を保持する。

- source file ID
- 相対パス
- シート名
- 行番号またはセル範囲
- Markdown見出し
- 取り込み日時
- ファイルSHA-256
- source scope
- source status
- owner

回答時には、社内向け表示として次のような出典を返せるようにする。

```text
参照: knowledge/procedures/account-request.xlsx / シート「申請先」 / 行12-18
```

絶対パスやOSユーザー名は表示しない。

## 検索時の優先順位

回答生成では、次の順序を基本とする。

1. 人間が承認した `knowledge_articles`
2. `authoritative` または `high` 指定された有効な取り込み資料
3. 通常優先度の有効な取り込み資料
4. `MEMORY.md` の用語・所在・ルーティング情報
5. 安全な公開質問だけGemini CLIでWeb調査
6. 根拠不足なら確認質問または `PENDING_HUMAN`

`MEMORY.md` は原則として回答本文の唯一の根拠にしない。どの資料を見るべきか、用語をどう解釈するか、何を優先するかを決める補助記憶として扱う。

`status=stale` の資料は警告付きで候補にできるが、`retired`、`forbidden`、期限切れ資料は通常回答へ使用しない。

複数資料が矛盾する場合は、次の順序で判断する。

- `authoritative` 指定
- 優先度
- 最終レビュー日
- 有効期限
- 人間承認済みFAQとの一致

解決できない場合は勝手に統合せず、人間担当へ回す。

## LangGraphへの追加

既存グラフへ最低限、次の処理を追加する。

```text
validate_question
  ↓
load_memory_context
  ↓
search_approved_knowledge
  ↓
search_imported_sources
  ↓
check_source_conflicts
  ↓
assess_answerability
```

- `load_memory_context`: 用語、参照先、禁止資料、ルーティング規則を取得する
- `search_imported_sources`: Excel・CSV・Markdown・テキスト由来のチャンクを検索する
- `check_source_conflicts`: 複数資料の矛盾、期限切れ、禁止状態を検査する

確認質問を生成するときも、メモリーと資料所在を先に確認し、資料に答えがあるのに質問者へ聞き返すことを避ける。

## CLI追加コマンド

最低限、次を実装する。名称は合理的に調整してよい。

```bash
python -m aifaq knowledge scan
python -m aifaq knowledge import
python -m aifaq knowledge import --path knowledge/procedures/example.xlsx
python -m aifaq knowledge list
python -m aifaq knowledge status
python -m aifaq knowledge rebuild-index
python -m aifaq memory validate
python -m aifaq memory show
python -m aifaq memory sync
python -m aifaq doctor
```

### `knowledge scan`

- 対応ファイルを列挙する
- Git追跡対象になっている内部資料を警告する
- 未登録資料、欠落資料、更新資料を表示する
- 内容をDBへ取り込まない

### `knowledge import`

- 差分だけ取り込む
- 成功・スキップ・警告・失敗を表示する
- 失敗した1ファイルのために全体を破壊しない

### `memory validate`

- 必須章の存在
- Source Mapの書式
- 相対パスの安全性
- 実ファイルの存在
- 重複ID
- 期限切れ・未レビュー
- `forbidden` 資料が検索対象に入っていないこと

を検査する。

### `memory sync`

Markdownを正としてSQLiteの `memory_entries` と同期する。DBからMarkdownを無断で上書きしない。
