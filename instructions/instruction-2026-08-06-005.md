## 2. Antigravity連携への移行

### 2.1 最重要方針

Antigravityのコマンド名、引数、出力形式を推測で実装しないこと。

まず、過去に動作した「人狼」「神託会議」のリポジトリ、設定、スクリプト、ログまたは引継ぎ資料を探し、実際に使用されている呼び出し方式を確認する。

確認できた実装方式を、必要最小限の変更でAI-FAQへ移植する。

過去実装を見つけられない場合は、その事実を記録し、現在のAntigravity環境で `--help`、バージョン表示、無害な最小実行を確認してから実装する。未確認の仕様を事実としてREADMEへ書かない。

### 2.2 Provider構成

既存の `ResearchProvider` 抽象は維持する。

最低限、次の構成にする。

```text
ResearchProvider
├─ AntigravityProvider     # 実環境用
└─ FakeResearchProvider    # 自動テスト用
```

Gemini固有のクラス、環境変数、doctor項目、`.gemini/settings.json` は、Antigravity移行後に不要なら削除する。

ただし、履歴や設計判断を消さないよう、変更理由をREADMEとresultへ記録する。

### 2.3 設定

特定製品名に固定しすぎない設定名へ変更する。

例:

- `AIFAQ_RESEARCH_PROVIDER=antigravity|fake`
- `AIFAQ_RESEARCH_BIN`
- `AIFAQ_RESEARCH_TIMEOUT`
- `AIFAQ_RESEARCH_WORKDIR`

既存環境変数との互換性を残す場合は、非推奨警告を出しREADMEへ記載する。

### 2.4 参照渡し

質問全文や長い調査指示をコマンドライン引数へ直接連結しない。

過去の「人狼」「神託会議」で利用した方式を優先し、公開可能な調査指示だけを一時ファイルへ書き、短い参照指示でAntigravityへ渡す。

一時ファイルには次だけを含める。

- 公開一般情報として安全判定済みの質問
- 出力JSONスキーマ
- 一次情報を優先する指示
- 回答、信頼度、警告、出典URLを返す指示

次は含めない。

- 社内資料本文
- `knowledge/internal/` の内容
- SQLite DB
- MEMORY.md内の内部情報
- 個人情報
- パスワード、トークン、認証情報
- 内部URL、IP、ホスト名、資産番号

一時作業ディレクトリはリポジトリ本体から分離し、終了後に安全に削除する。失敗時も可能な範囲で清掃する。

### 2.5 出力検証

Antigravityの出力はそのまま信用しない。

- 終了コードを確認
- stdout/stderrをサイズ制限
- タイムアウトを設定
- JSONまたは結果ファイルをPydanticで検証
- URL形式を検証
- 空回答、壊れたJSON、出典なし、低信頼度を人間回答待ちへ送る
- Markdownコードフェンス付きJSONなど、実環境で確認された揺れだけを安全に正規化する
- 不明な形式を推測で成功扱いしない

## 3. 実機スモークテスト

実Antigravityを使うテストは、公開情報だけの無害な質問で行う。

例:

> Windows 11でネットワークアダプターを再起動する公式手順は？

記録する内容:

- 実行日時
- Antigravityのバージョン
- 実際に使用したコマンド形式（秘密情報は除外）
- 終了コード
- 出力形式
- 取得できた出典
- タイムアウト有無
- 成功または失敗理由

実環境が利用不能、認証不可、非対話実行不可などの場合は、成功を装わず `SUCCESS_WITH_LIMITATIONS` または `BLOCKED` とする。

## 4. CLIで確認する一連の実動作

最低限、次を順番に確認する。

### 4.1 承認済み知識

1. 人間承認済みFAQを登録
2. 類似質問を実行
3. 外部Providerを呼ばずに回答
4. 知識ID、版、出典を表示

### 4.2 最大3回の確認質問

1. 情報不足の質問を実行
2. `aifaq reply` で回答
3. 必要に応じて再質問
4. 3回を超えない
5. 情報が揃えば途中で回答へ進む

### 4.3 公開情報のWeb調査

1. 承認済み知識にない公開一般質問を実行
2. Antigravityを呼び出す
3. 出典付き暫定回答を表示
4. 自動的には承認済み知識へ保存しない

### 4.4 内部質問の遮断

1. 社内手順または秘密情報を含むテスト質問を実行
2. Antigravityを一度も呼ばない
3. 社内知識または人間回答待ちへ進む

テストではProviderの呼び出し回数が0であることを明示検証する。

### 4.5 人間回答による学習

1. 人間回答待ちを作成
2. IT管理者が回答・承認
3. SQLiteへ承認済み知識として保存
4. 次回の類似質問で再利用

### 4.6 ファイル知識とMEMORY.md

1. 安全なサンプルExcelまたはCSVを取り込む
2. MarkdownまたはTXTを取り込む
3. `MEMORY.md` の索引から参照優先度を確認
4. ファイル、Excelシート、行範囲を出典として表示
5. ファイル更新後の差分取り込みを確認

## 5. 残課題の実装

### 5.1 AI調査結果の人間承認

AI調査結果を人間が確認・必要に応じて修正し、承認済み知識へ昇格できるCLIを追加する。

コマンド例:

```bash
aifaq research list
aifaq research show 12
aifaq research approve 12 --approved-by NAME
aifaq research approve 12 --approved-by NAME --answer-file corrected.md
```

要件:

- 元のAI回答と出典を保持
- 承認者、承認日時、修正有無、変更理由を記録
- 承認時に `knowledge_articles` と `knowledge_revisions` へ保存
- 同じresearch runの二重承認を防止
- 却下または期限切れも管理できる設計を検討

### 5.2 `source_import_runs` の実書き込み

取り込み単位で次を保存する。

- 開始・終了日時

- 実行者または実行元
- 検出、追加、更新、スキップ、欠落、失敗件数
- エラー概要
- 成否

### 5.3 PythonバージョンとCI

- Python 3.13

実AI CLIはCIで呼ばず、FakeProviderを使用する。

### 5.4 CLIテスト

既存84テストを維持し、追加機能をテストする。

特に次を追加する。

- Antigravity出力の正常・異常・空出力
- タイムアウト
- 非ゼロ終了コード
- research approveの正常系・二重承認・修正版
