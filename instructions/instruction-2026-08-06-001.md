# instruction-2026-08-06-001

## 目的

空の `garyohosu/AI-FAQ` リポジトリに、社内IT管理部門向けの「学習型AI FAQ」MVPを実装する。

利用する中心技術は次のとおり。

- Python 3.12
- LangGraph
- Pydantic v2
- SQLite 3 / FTS5
- Gemini CLI（クラウドAPIをコードから直接呼ばない）
- pytest

このシステムは次の順序で質問に対応する。

1. 社内で承認済みの知識を検索する
2. 十分に一致する承認済み知識があれば、それを最優先で回答する
3. 承認済み知識がなく、一般公開情報で回答可能な質問なら、Gemini CLIにインターネット調査を依頼する
4. AI調査だけで安全かつ十分に回答できれば、出典付きの暫定回答を返す
5. 社内固有情報、セキュリティ上重要な質問、根拠不足、低信頼度の場合は、人間回答待ちとして保存する
6. 人間のIT管理者が回答した内容は、承認済み知識としてSQLiteへ保存する
7. 次回以降の類似質問では、その人間回答を優先して利用する

ここでいう「学習」はモデルの再学習ではない。人間が回答・承認した知識を、版管理されたナレッジとして蓄積し、検索して再利用する仕組みとする。

## 最重要原則

- 人間が承認した社内知識を最優先する。
- AIのインターネット回答を自動的に社内知識へ昇格させない。
- 一般社員の質問やAI回答を無条件で学習しない。
- 社内固有情報、個人情報、認証情報、内部URL、IPアドレス、ホスト名、資産番号などを外部AIへ送らない。
- 外部調査は、公開情報だけで回答できる一般的なIT質問に限定する。
- AI回答には出典、調査日時、回答種別を明示する。
- 危険な操作、権限変更、アカウント削除、ネットワーク遮断などは自動実行しない。FAQとして手順を示すだけにする。
- `shell=True` は禁止する。CLI呼び出しは引数配列と標準入力を使う。
- Gemini CLIに `--yolo` を付けない。
- テストは外部AIやネットワークを呼ばず、モックで完結させる。

## 想定ユースケース

### 承認済み知識から回答

質問:

> 社内Wi-Fiのパスワードを忘れました。

承認済みナレッジが存在する場合:

- 社内ナレッジのみから回答する
- 外部AIには送信しない
- ナレッジIDと版番号を表示する

### インターネット調査で回答

質問:

> Windows 11でネットワークアダプターを再起動する方法は？

社内ナレッジがない場合:

- 公開情報として扱えるか判定する
- Gemini CLIのWeb検索を使う
- Microsoftなど一次情報を優先する
- 出典URLと調査日を付けて暫定回答する
- 自動的には社内ナレッジへ保存しない

### 人間回答待ち

質問:

> 第2工場の検査PCを交換するときの申請先は？

これは社内固有情報なので外部へ送らない。

- `PENDING_HUMAN` として保存する
- IT管理者がCLIから回答する
- 回答を承認済みナレッジとして保存する
- 次回から類似質問へ再利用する

## SQLite設計

SQLiteはアプリの業務データとLangGraphチェックポイントに利用する。

最低限、次のテーブルを作成する。

### `knowledge_articles`

承認済み知識の本体。回答の更新時は既存行を破壊的に上書きするだけでなく、履歴を追跡できるようにする。

### `knowledge_revisions`

各版の質問、回答、変更者、変更日時、変更理由を保持する。

### `question_variants`

同じ知識へ紐づく別表現の質問を保持する。

### `pending_questions`

人間回答待ちの質問を保持する。

最低限の状態:

- `OPEN`
- `ANSWERED`
- `CANCELLED`

### `query_history`

質問、分類、採用した経路、回答種別、参照知識、調査実行ID、日時を保持する。

### `research_runs`

Gemini CLIの実行結果、終了コード、調査日時、使用ツール統計、出典、エラー概要を保持する。秘密情報や巨大な生出力は保存しない。

### FTS5

`knowledge_articles` と `question_variants` を検索できるFTS5インデックスを作る。

- `canonical_question`
- `answer`
- `tags`
- `question_variants`

を検索対象にする。

FTS5が利用できないPython/SQLite環境では、明確なエラーを出すか、LIKE検索へ安全にフォールバックする。`doctor` コマンドで確認できるようにする。

検索は、完全一致・正規化一致を最優先し、その後FTS5のBM25順位を利用する。閾値は設定ファイルで変更可能にする。

## LangGraph設計

StateGraphを使い、最低限次のノードを持たせる。

```text
START
  ↓
validate_question
  ↓
classify_question
  ↓
search_approved_knowledge
  ↓
route_after_search
  ├─ 高一致かつ有効な承認済み知識 → compose_knowledge_answer → record_history → END
  ├─ 外部調査禁止                        → request_human → END/interrupt
  └─ 公開情報として外部調査可能          → research_with_cli
                                             ↓
                                        validate_research
                                             ↓
                                        route_after_research
                                          ├─ 十分な根拠 → compose_research_answer → record_history → END
                                          └─ 根拠不足   → request_human → END/interrupt
```

LangGraphの永続化には `SqliteSaver` または `AsyncSqliteSaver` を使い、`thread_id` を必須とする。

人間回答待ちではLangGraphの `interrupt()` を利用する設計を基本とする。ただしCLIを一度終了しても、同じ `thread_id` で再開できること。

`interrupt()` より前の副作用は再実行されても壊れないように冪等にする。

## 質問分類

分類をAIだけに任せない。まず決定論的なルールで外部送信禁止候補を検出する。

例:

- パスワード、秘密鍵、トークン、認証コード
- 個人名と社員番号の組み合わせ
- メールアドレス、電話番号
- 社内IP、ホスト名、内部ドメイン
- 工場名、設備名、資産番号、社内システム固有名
- 「社内」「弊社」「当社」「申請先」「担当者」「共有フォルダ」など社内手順を示す語
- アカウント停止、権限付与、退職者処理など重要操作

検出した場合は、質問本文をGemini CLIへ渡さず `PENDING_HUMAN` にする。

単純なマスキング後に外部送信する方式はMVPでは採用しない。誤送信より回答待ちを優先する。

## Gemini CLIプロバイダー

### 目的

PythonからクラウドAPI SDKを直接使わず、Gemini CLIのヘッドレスモードを利用して公開情報を調査する。

### 実行方法

- `subprocess.run()` を使用する
- `shell=False`
- コマンドはリストで渡す
- 質問をシェルコマンドへ連結しない
- 長いプロンプトは標準入力で渡す
- `--output-format json` を利用する
- タイムアウトを設定する
- stdout/stderrの最大保存量を制限する
- 終了コードとJSON構造を検証する
- CLI未導入、未ログイン、利用制限、タイムアウト、JSON破損を別エラーとして扱う

概念例:

```python
subprocess.run(
    ["gemini", "--output-format", "json"],
    input=prompt,
    text=True,
    capture_output=True,
    timeout=config.research_timeout_seconds,
    check=False,
)
```

実際の引数は、実装時点のローカル `gemini --help` と公式ドキュメントで確認する。

### `.gemini/settings.json`

このプロジェクトではGemini CLIの機能をWeb調査に限定する。

- Web検索とWeb取得だけを許可する
- シェル実行、ファイル書換、メモリ保存などは無効化する
- `--yolo` は使わない
- リポジトリ全体をコンテキストへ渡さない

設定キーとツール名は、実装時点の公式仕様に合わせること。

### 調査プロンプト

Gemini CLIへは次を要求する。

- 公開情報のみで回答する
- 可能な限り一次情報・公式情報を優先する
- 重要な主張ごとに出典URLを付ける
- 情報の日付を確認する
- 社内固有の事実を推測しない
- 不明な場合は不明と回答する
- JSON本文として、回答、出典、信頼度、警告を返す

Gemini CLI全体のJSON包みの `response` 内に、アプリ用JSONを返させる場合は、コードフェンスを除去してPydantic検証する。検証失敗時は一度だけ修正要求を出してよい。二度目も失敗したら人間回答待ちにする。

### プロバイダー抽象化

`ResearchProvider` ProtocolまたはABCを定義する。

```python
class ResearchProvider(Protocol):
    def research(self, question: str) -> ResearchResult: ...
```

MVPでは次を実装する。

- `GeminiCLIProvider`
- `FakeResearchProvider`（テスト専用）

Codex CLI、Claude Code CLI、Ollamaなどは今回実装必須ではない。ただし、後から追加できる構造にする。

## 人間回答と学習

### 人間回答

IT管理者が次のようなCLIで回答できるようにする。

```bash
python -m aifaq pending list
python -m aifaq pending show 12
python -m aifaq pending answer 12 --by hantani
```

回答本文は、対話入力、標準入力、または `--file` で受け付ける。コマンドライン引数へ長文を直接書かせなくてもよい。

人間回答時に次を入力・生成する。

- 正式回答
- カテゴリ
- タグ
- 別表現の質問
- 有効期限（任意）
- 回答者
- 変更理由

人間回答は `source_type=HUMAN`、`status=APPROVED` として保存する。

### AI調査回答の承認

AI調査回答は自動学習しない。

必要なら管理者が明示的に承認してナレッジ化できるコマンドを用意する。

```bash
python -m aifaq research approve <research_id> --by hantani
```

承認時は内容を編集でき、`source_type=APPROVED_AI` として保存する。
