## 最終目標

Python 3.12、LangGraph、Pydantic v2、SQLite、Gemini CLIを用いたCLIアプリケーションを完成させてください。

最低限、次を実現してください。

- 承認済み社内知識を最優先して回答する
- 知識が不足している場合、質問者へ最大3ラウンドの確認質問を行う
- 公開一般情報だけで回答可能な場合は、Gemini CLIでWeb調査する
- 社内固有情報、機密情報、個人情報、認証情報を外部AIへ送信しない
- AI調査結果を自動的に承認済み知識へ昇格させない
- 人間のIT管理者が回答・承認した内容をSQLiteへ保存し、次回から再利用する
- Excel、CSV、TSV、Markdown、テキストの知識資料を取り込む
- `MEMORY.md` と `memory/*.md` を、知識の所在、用語、判断、優先順位、不足知識の索引として使う
- LangGraphのチェックポイントをSQLiteへ保存し、`thread_id`で確認質問や人間回答待ちを再開できる
- 回答に、参照した知識ID、ファイル、Excelシート、行範囲、URLなどの出典を付ける

## 実装方針

### 1. アーキテクチャ

責務を最低限、次の層に分離してください。

- CLI層
- LangGraphワークフロー層
- Pydanticモデル層
- SQLiteリポジトリ層
- 知識検索・取り込み層
- メモリー索引層
- セキュリティ・外部送信可否判定層
- AI CLIプロバイダー層

Gemini CLIへ密結合させず、将来Claude Code、Codex CLI、ローカルLLMへ差し替えられるプロバイダーインターフェースを作ってください。

### 2. 回答フロー

概ね次のグラフを実装してください。

```text
START
  ↓
validate_question
  ↓
security_precheck
  ↓
load_memory_index
  ↓
search_approved_knowledge
  ↓
evaluate_sufficiency
  ├─ 十分な承認済み知識あり → compose_knowledge_answer → record_history → END
  ├─ 情報不足かつ確認回数 < 3 → generate_clarification → interrupt
  │                                      ↓ reply
  │                                 merge_context
  │                                      ↓
  │                            security_precheckへ戻る
  ├─ 公開一般情報として外部調査可能 → research_with_cli
  │                                      ↓
  │                                 validate_research
  │                                      ↓
  │                       十分 → compose_research_answer → record_history → END
  │                       不十分 → request_human → interrupt
  └─ 内部・機密・危険・上限到達 → request_human → interrupt
```

確認質問は1ラウンド1問とし、最大3回です。必要な情報が揃えば直ちに先へ進めてください。4回目の確認質問は生成禁止です。

### 3. 学習とメモリー

ここでいう学習はモデル再訓練ではありません。

- 人間が回答・承認したFAQをSQLiteの版管理された知識として保存する
- 同じ質問の別表現を `question_variants` に保存する
- `MEMORY.md` は知識ファイルの所在と優先順位を示す総合索引とする
- `memory/terminology.md` は社内用語
- `memory/source-notes.md` は資料の優先度、注意、参照禁止情報
- `memory/decisions.md` は管理者判断
- `memory/gaps.md` は未解決・不足知識
- AIはメモリー変更案を提案できるが、承認なしで正式記憶へ反映しない

### 4. 知識資料

次のフォルダを作成してください。

```text
knowledge/
├─ README.md
├─ public/
├─ internal/
├─ policies/
├─ procedures/
├─ troubleshooting/
├─ inventory/
└─ inbox/
```

実データの社内資料を公開リポジトリへ入れないでください。安全なサンプルだけを作成してください。

対応形式:

- `.xlsx`
- `.xlsm`（マクロを実行しない）
- `.csv`
- `.tsv`
- `.md`
- `.txt`

Excelは `openpyxl` の `read_only=True`、`data_only=True` を基本としてください。マクロ、外部リンク、数式を実行しないでください。

ファイルのSHA-256を保存し、未変更ファイルを再取り込みしない差分取り込みを実装してください。ファイル削除時は即座に履歴を破壊せず、`MISSING`などの状態で管理してください。

### 5. セキュリティ

次を外部AIへ送信しないでください。

- パスワード、秘密鍵、トークン、認証コード
- 個人情報
- 社内IP、ホスト名、内部ドメイン、内部URL
- 社内システム名、設備名、資産番号
- 工場、部門、担当者、申請先などの社内固有手続き
- `knowledge/internal/`、`memory/`、SQLiteにある内部本文

公開一般質問であることを決定論的ルールで確認した後に限り、外部調査を許可してください。迷う場合は外部送信せず、人間へ引き継いでください。

CLI実行では次を守ってください。

- `subprocess.run()`
- `shell=False`
- コマンドは引数配列
- プロンプトは標準入力
- タイムアウトあり
- stdout、stderrの保存量制限
- JSON出力をPydanticで検証
- `--yolo`禁止
- ファイル変更、シェル実行など不要なGemini CLIツールを許可しない

外部ネットワークや実Gemini CLIを呼ばず、FakeProviderまたはモックで完結するテストを作成してください。

最低限、次を検証してください。

- Pydanticモデルの正常・異常入力
- SQLite初期化とマイグレーション
- 承認済み知識の検索優先
- AI回答が自動学習されない
- 人間回答が承認知識として保存される
- 確認質問が最大3回で止まる
- 4回目が生成されない
- 回答済み情報を再質問しない
- 「分からない」が続いた場合の人間引き継ぎ
- 内部質問をGemini CLIへ送らない
- 秘密情報を含む質問を外部へ送らない
- 公開一般質問だけがFakeProviderへ送られる

- SHA-256による差分取り込み

- 出典情報の保持
- LangGraphの中断・再開
- CLIの主要経路

`pytest`を全件実行し、可能ならカバレッジも計測してください。テスト失敗を残したまま成功扱いにしないでください。
