## 追加目的

質問を1回受け取って即座に回答・外部調査・人間転送するだけではなく、回答に必要な情報が不足している場合、AI FAQが質問者へ確認質問を行えるようにする。

確認質問は最大3ラウンドとする。ただし、必要な情報が揃った時点で直ちに確認を終了し、承認済み知識の検索、外部調査または人間回答待ちへ進む。

3ラウンドはMVPの固定上限とする。4回以上の聞き返しは利用者負担が大きく、FAQより聞き取り業務に近くなるため採用しない。設定値として減らすことは許可するが、3を超えてはならない。

## 基本動作

次の順序で処理する。

```text
質問を受信
  ↓
入力・機密性を検査
  ↓
承認済み知識を検索
  ↓
現時点で安全かつ十分に回答可能か判定
  ├─ 回答可能 → 回答を生成
  ├─ 情報不足かつ確認回数 < 3 → 質問者へ確認質問 → 回答を受信して再評価
  └─ 情報不足かつ確認回数 = 3 → PENDING_HUMAN
```

確認回答を受け取った後は、元の質問を破壊的に書き換えず、元質問と確認履歴を保持したまま検索・分類・回答可能性を再評価する。

## 確認質問の品質要件

各ラウンドでは、回答に最も影響する不明点を1つだけ質問する。

- 一度に複数の論点を質問しない
- 同じ内容を言い換えて再質問しない
- 既に質問者が回答した情報を再度聞かない
- 「詳しく教えてください」のような漠然とした聞き方を避ける
- 選択肢を提示できる場合は、2から4個の具体的な選択肢を示す
- 自由入力が必要な場合は、何を入力すべきか具体例を示す
- パスワード、秘密鍵、認証コード、個人情報そのものを入力させない
- 機密情報が必要に見える場合は、それを質問せず人間担当へ引き継ぐ
- 質問者が「分からない」「確認できない」と答えた場合、同じ情報を再要求せず、別経路または人間担当へ進む

良い例:

> 対象端末のOSはどれですか？ Windows 10 / Windows 11 / その他

> エラーはサインイン前とサインイン後のどちらで表示されますか？

悪い例:

> OS、端末名、利用場所、エラー内容、発生日時を全部教えてください。

## 代表的な確認項目

質問分類ごとに、決定論的な候補を用意する。

- Windows: OSバージョン、表示されたエラー、発生タイミング、全端末か1台だけか
- ネットワーク: 有線・無線、全員・本人のみ、接続先、インターネットのみか社内資源も不可か
- アカウント: 対象サービス、サインイン可否、エラー種別。ただし認証情報は聞かない
- ハードウェア: 機器種別、症状、電源状態、他端末での再現有無
- ソフトウェア: 製品名、バージョン、操作手順、エラー内容
- 社内手続き: 対象手続き、所属区分、拠点。ただし外部AIへ送信しない

ルールで適切な確認項目を選べない場合のみAIによる質問生成を利用する。

## 外部AI利用の制限

Gemini CLIへ確認質問の生成を依頼できるのは、`safe_for_external_research=true` の公開一般質問に限る。

内部情報、個人情報、セキュリティ上重要な質問では、元質問や確認回答をGemini CLIへ送らない。これらの確認質問は、決定論的ルールとテンプレートで生成する。適切な安全質問を作れない場合は、即座に `PENDING_HUMAN` へ進む。

Gemini CLIに確認質問を生成させる場合も、出力はPydanticで検証し、質問文1件と任意の選択肢だけを採用する。CLIに質問者との会話制御を直接任せない。

## Pydanticモデルの追加・変更

### QuestionRequest

既存項目に加えて、必要に応じて以下を保持する。

- `original_question: str`
- `clarification_round: int`（0から3）
- `clarification_history: list[ClarificationTurn]`

`question` を現在の合成質問として持つ場合でも、`original_question` は必ず保持する。

### ClarificationTurn

最低限、次の項目を持つ。

- `round_no: int`（1から3）
- `question: str`
- `answer: str | None`
- `options: list[str]`
- `reason: str`
- `asked_at: datetime`
- `answered_at: datetime | None`

### ClarificationDecision

- `needs_clarification: bool`
- `missing_information: list[str]`
- `next_question: str | None`
- `options: list[str]`
- `reason: str`
- `can_answer_now: bool`
- `must_escalate: bool`

次を検証する。

- `clarification_round` は0から3
- `needs_clarification=true` なら `next_question` が必須
- `next_question` は1件のみで、空文字を禁止
- 選択肢は0個または2から4個
- 過去の質問との正規化一致・高類似を拒否する

### FAQAnswer

`answer_type` に以下を追加する。

- `NEEDS_CLARIFICATION`

確認要求を返す場合は、少なくとも次を含める。

- `thread_id`
- `clarification_round`
- `question`
- `options`
- `remaining_rounds`

## LangGraphの変更

次のノードを追加する。名称は合理的に調整してよい。

```text
validate_question
  ↓
classify_question
  ↓
search_approved_knowledge
  ↓
assess_answerability
  ├─ 回答可能 → 既存回答経路
  ├─ 要確認かつ round < 3 → create_clarification_question
  │                              ↓
  │                         ask_requester / interrupt
  │                              ↓
  │                         merge_clarification
  │                              ↓
  │                         classify_questionへ戻る
  └─ 要確認かつ round >= 3 または安全に質問不能 → request_human
```

`ask_requester` はLangGraphの `interrupt()` を使用し、CLI終了後も同じ `thread_id` で再開できること。

再開時は次を保証する。

- 回答を直前の未回答 `ClarificationTurn` にだけ紐付ける
- 同じ回答を二重登録しない
- 確認回数を二重加算しない
- 途中でプロセスが停止しても状態がSQLiteから復元される
- 3回目の回答後は4回目の質問を生成しない

## SQLiteの追加

### `clarification_turns`

最低限、次を保存する。

- `id`
- `thread_id`
- `round_no`
- `question`
- `answer`
- `options_json`
- `reason`
- `asked_at`
- `answered_at`

`UNIQUE(thread_id, round_no)` を設定する。

確認履歴は監査可能にするが、秘密情報を保存しない。入力に秘密情報らしき値を検出した場合は、保存前に拒否または安全な要約へ置換する。

## CLI仕様の追加

対話端末では、1つの実行内で最大3回まで確認質問を表示し、回答を受け取って続行できるようにする。

非対話利用と中断再開のため、最低限次に相当するコマンドを用意する。

```bash
aifaq ask "質問文" --thread-id THREAD_ID
aifaq reply --thread-id THREAD_ID "確認質問への回答"
```

`ask` の結果が確認待ちの場合、JSON出力では次に相当する形式を返す。

```json
{
  "answer_type": "NEEDS_CLARIFICATION",
  "thread_id": "...",
  "clarification_round": 1,
  "question": "対象端末のOSはどれですか？",
  "options": ["Windows 10", "Windows 11", "その他"],
  "remaining_rounds": 2
}
```

`reply` は同じ `thread_id` の未回答確認質問が1件だけ存在する場合に限り受理する。該当なし、複数存在、既回答の場合は明確なエラーを返す。

## 人間担当への引き継ぎ

次の場合は確認回数を使い切る前でも人間担当へ進める。

- 安全な確認質問を作れない
- 秘密情報の提示が必要に見える
- セキュリティ事故、権限変更、アカウント停止など緊急性が高い
- 質問者が人間対応を希望した
- 質問者が2回連続で「分からない」「不明」と回答した
- 確認回答同士が矛盾し、機械的に解決できない

人間担当が回答するときは、元質問と確認履歴をまとめて確認できるようにする。

## テスト追加

外部CLIとネットワークはすべてモックし、最低限次をテストする。

1. 情報が十分なら確認せず回答する
2. 1回の確認で情報が揃い回答する
3. 2回の確認で情報が揃い回答する
4. 3回目の確認後に回答する
5. 3回で不足した場合は `PENDING_HUMAN` になる
6. 4回目の質問が絶対に生成されない
7. 同じ質問を繰り返さない
8. 過去に回答済みの項目を再質問しない
9. `thread_id` で中断・再開できる
10. 再開を重ねても回数が二重加算されない
11. 内部質問がGemini CLIへ送られない
12. パスワードや認証コードを尋ねる質問が拒否される
13. 質問者が人間対応を希望すると即時エスカレーションする
14. 「分からない」が2回続くと人間担当へ進む
15. CLIの `ask` と `reply` がJSON形式で正しい状態を返す

## READMEの追加説明

READMEに次を明記する。

- 確認質問は最大3回で、必要な情報が揃えば早く終了する
- 3回で解決しない場合は人間のIT担当へ引き継ぐ
- パスワードや認証コードを尋ねることはない
- `thread_id` により後から会話を再開できる
- AIの会話内容そのものをモデル再学習する仕組みではない
